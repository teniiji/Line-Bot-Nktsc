ไลน์ OA ตอบคำถามสมาชิกสหกรณ์ออมทรัพย์ครูหนองคาย จำกัด
(Next.js App Router + TypeScript + Prisma/PostgreSQL + Claude API)

## 🤖 ระบบการทำงานหลัก (System Architecture)
บอทรับ Webhook จาก LINE -> เรียกใช้งาน Claude (Tool-use Agent) ใน `lib/financeAgent.ts` (ตัว runner — ส่วนประกอบแยกอยู่ใน `lib/agent/`: types, state, tools, prompts, forwarding, handlers) เพื่อประมวลผล:
1. **บันทึกรายการ:** ตรวจสอบสลิป (ยอดตรง, บัญชีปลายทางต้องเป็นสหกรณ์ — มีชั้นตรวจซ้ำในโค้ด `lib/recipientCheck.ts` ปฏิเสธสลิปที่ผู้รับเป็นบุคคลธรรมดาเสมอไม่พึ่งดุลยพินิจโมเดล, ป้องกันสลิปซ้ำด้วย SHA-256) และแยกประเภทรายการ (ฝากเงิน, ซื้อหุ้น, ชำระหนี้) — ธุรกรรม "ชำระหนี้" ต้องระบุประเภทเงินกู้เพิ่ม และ "ฝากเงิน" ต้องระบุเลขที่บัญชีที่จะฝากเพิ่ม ก่อนจะบันทึกจริง — ถ้าชื่อในช่อง "จาก" ของสลิปไม่ตรงกับชื่อสมาชิกที่ลงทะเบียนไว้ (`lib/nameMatch.ts`, เทียบแบบยืดหยุ่น ไม่นับคำนำหน้า/เว้นวรรค) ต้องให้สมาชิกยืนยันก่อนด้วยว่าเป็นธุรกรรมของตัวเองจริง — รับสลิป/เอกสารประกอบทั้งแบบรูปภาพและไฟล์ PDF (ไฟล์ประเภทอื่นที่ไม่ใช่ PDF จะได้รับแจ้งว่าไม่รองรับ) เก็บ `slipIsPdf`/`imageIsPdf` ไว้เพื่อให้การส่งต่อรู้ว่าต้องส่งเป็นข้อความลิงก์แทนข้อความรูปภาพ เพราะ LINE Messaging API ส่งไฟล์แนบให้เจ้าหน้าที่ไม่ได้ ส่งได้แค่รูปภาพเท่านั้น
2. **ยืนยันตัวตน:** เทียบข้อมูลกับฐานข้อมูลทะเบียนสมาชิก (`MemberRoster`) 
3. **ระบบตอบคำถาม (Knowledge Base):** ตอบคำถามอัตราดอกเบี้ย/สวัสดิการ/ช่องทางชำระยอดหักไม่ได้/เกณฑ์สิทธิ์กู้เงินทั่วไป จากตาราง `KnowledgeEntry` (Fallback ไปที่ `lib/knowledge.ts` — เนื้อหาสกัดมาจากประวัติแชทจริงใน LINE OA ที่เจ้าหน้าที่ตอบ) 
4. **ความปลอดภัย:** กรองลิงก์ทั้งหมดออกจากคำตอบผ่าน `stripDisallowedLinks` (`lib/links.ts`) — allowlist ปกติว่างเปล่าตั้งแต่มีเหตุการณ์ LINE ดึง preview การ์ดพนันมาแสดงคู่กับโดเมนสหกรณ์เอง (`nktscoop.com`, ต้องสงสัยว่าโดน cloaking) ข้อยกเว้นเดียวคือลิงก์แบบฟอร์ม (ข้อ 5 ด้านล่าง) ที่เจ้าหน้าที่กรอกเองผ่านแดชบอร์ด — ส่งเฉพาะโฮสต์ของลิงก์เหล่านั้นเข้าไปเป็น `extraAllowedHosts` ต่อคำขอ ไม่ได้แก้ allowlist หลัก
5. **ลิงก์แบบฟอร์ม:** เมื่อสมาชิกขอแบบฟอร์ม (เช่น "ขอแบบฟอร์มกู้เงินสามัญ") บอทตรวจตาราง `FormLink` ก่อน — ถ้ามีแบบฟอร์มที่ตรงกัน ตอบลิงก์นั้นแบบเต็มได้ทันที (ข้อยกเว้นเดียวจากกฎห้ามพิมพ์ลิงก์ในข้อ 4) ถ้าไม่มีในรายการ กลับไปแนะนำให้ติดต่อสำนักงานเหมือนเดิม ดูรายละเอียดที่หัวข้อ "ลิงก์แบบฟอร์ม" ด้านล่าง
6. **ค้นหาเลขสมาชิก:** เมื่อสมาชิกถามหาเลขสมาชิกของตัวเอง บอทต้องขอยืนยันตัวตนก่อนเสมอ 3 อย่าง (ชื่อ-นามสกุล, เลขประจำตัวประชาชน 13 หลัก, เบอร์โทรที่ลงทะเบียนไว้) แล้วตรวจกับ `MemberRoster` แบบ exact match (`lib/memberLookup.ts` — เทียบเลขบัตร/เบอร์โทรแบบตัดขีด/เว้นวรรคออกก่อน, เทียบชื่อแบบเดียวกับ `nameMatch.ts`) ไม่ตรงครบทั้ง 3 อย่างจะไม่บอกเลขสมาชิกเด็ดขาด และไม่บอกว่าช่องไหนผิดเพื่อกันการเดา — ถ้าสมาชิกโทรมาแจ้งเปลี่ยนเบอร์โทรหรือแจ้งว่าเลขบัตรที่มีอยู่ผิด เจ้าหน้าที่แก้ไขได้จากหน้า dashboard โดยตรง (แท็บ "สมาชิก LINE" > "แก้ไขข้อมูลยืนยันตัวตนสมาชิก", `components/MemberContactPanel.tsx` / `app/api/member-roster/`) — จงใจไม่เปิดให้สมาชิกแก้เองผ่านบอท เพราะ 2 ช่องนี้คือช่องที่ใช้ยืนยันตัวตนก่อนบอกเลขสมาชิก ถ้าให้แก้เองได้จะเท่ากับให้ใครก็ตาม "รีเซ็ต" ข้อมูลยืนยันตัวตนเป็นค่าที่ตัวเองคุมได้ ตัวตรวจรูปแบบ (13 หลัก / เบอร์ 9-10 หลัก) ใช้ร่วมกับสคริปต์ `import-national-id-phone.ts` ผ่าน `lib/identityFormat.ts`
7. **คำขอที่ไม่มีเอกสารแนบ (เช่น ลืมรหัสผ่าน/เข้าแอปไม่ได้):** บอทไม่มีความสามารถรีเซ็ตรหัสผ่านเอง ต้องส่งต่อให้เจ้าหน้าที่เสมอ — ใช้ tool `request_staff_help` เริ่ม flow เดียวกับคำขอที่มีเอกสารแนบ (`flag_supporting_document` → `submit_service_purpose`) แต่ข้ามขั้นตอนที่ต้องมีเอกสาร สร้าง `PendingServiceRequest` ทันทีจากข้อความล้วน (`documentType` เป็นค่าคงที่ `NO_DOCUMENT` — ดู `lib/documentTypes.ts`) แล้วขอชื่อ-นามสกุล/เลขสมาชิก/เบอร์โทรติดต่อกลับต่อก่อนส่งต่อแผนก "สารสนเทศ" เหมือน flow ปกติทุกประการ (share โค้ดผ่าน `advanceServiceRequest` ใน `lib/agent/handlers.ts`)

### 🎯 การจับคู่ผู้รับผิดชอบเรื่องกู้เงิน (Loan Routing)
คำขอที่แผนก "สินเชื่อ" หาผู้รับตามลำดับความสำคัญ (`resolveForwardTargets` ใน `lib/agent/forwarding.ts`, precedence อยู่ใน `lib/loanRouting.ts`):
1. **รหัสผู้รับผิดชอบรายบุคคล** (`MemberRoster.responsibleCode` จับคู่ `ResponsibleContact.code`) — วิธีหลัก แม่นยำกว่าเพราะเป็นรหัสสั้นๆ ไม่ใช่ข้อความอิสระ จัดการได้จากหน้า dashboard ("ผู้รับผิดชอบเรื่องกู้เงิน") โดยตรง หรือนำเข้าเป็นชุดด้วย `import-responsible-contacts.ts`
2. **ชื่อหน่วยงาน** (`MemberRoster.unitName` จับคู่ `LoanDistrictContact.unitName` แบบตรงตัว) — fallback สำรอง นำเข้าด้วย `import-loan-contacts.ts`
3. **`LINE_FORWARD_LOAN_ID`** — fallback สุดท้ายเมื่อไม่มีทั้งสองข้อบน

### 🏢 การส่งต่อคำขอตามแผนก (Department Routing)
แผนกอื่นที่ไม่ใช่สินเชื่อ (เงินฝาก, สารสนเทศ, สวัสดิการ, นิติการ, บัญชี, ฌาปนกิจ, บริหารสำนักงาน/ธุรการ, อื่นๆ — รายชื่ออยู่ใน `lib/departments.ts`) ส่งต่อผ่านตาราง `DepartmentContact` (precedence อยู่ใน `lib/departmentRouting.ts`):
1. **ส่งหาเจ้าหน้าที่ทุกคนที่ตั้งไว้ในแผนกนั้นพร้อมกัน** (broadcast) — กันคำขอตกหล่นเพราะไม่ต้องรู้ว่าใครอยู่เวร จัดการเจ้าหน้าที่ต่อแผนกได้จากหน้า dashboard โดยตรง ไม่ต้อง deploy ใหม่
2. **`LINE_FORWARD_GENERAL_ID`** — fallback เมื่อแผนกนั้นยังไม่มีเจ้าหน้าที่ตั้งไว้เลย

ถ้าส่งสำเร็จอย่างน้อย 1 คน ระบบจะถือว่าคำขอ "ส่งต่อสำเร็จ" (แจ้งสมาชิกตามนั้น) แต่จะบันทึกใน `ServiceRequestLog.forwardedTo` ว่าใครล้มเหลวด้วย เผื่อเจ้าหน้าที่บางคน LINE ID ใช้ไม่ได้แล้วให้เจ้าของระบบสังเกตเห็นและแก้ไข

### 🔗 ลิงก์แบบฟอร์ม (Form Links)
เมื่อสมาชิกขอแบบฟอร์ม/เอกสารของสหกรณ์ (เช่น แบบฟอร์มกู้เงินสามัญ, สสค., ใบสมัครสมาชิก) บอทตรวจตาราง `FormLink` (จัดการได้จากแดชบอร์ด แท็บ "ฐานความรู้" > "ลิงก์แบบฟอร์ม", `components/FormLinksPanel.tsx` / `app/api/form-links/`) — แต่ละแถวมี `key`/`label`/`url` แยกตามประเภทฟอร์ม ถ้ามีแบบฟอร์มที่ตรงกับที่ผู้ใช้ขอ บอทตอบลิงก์นั้นแบบเต็มได้ทันที ถ้าไม่มี (หรือยังไม่ได้ตั้งค่าเลย) กลับไปแนะนำให้ติดต่อสำนักงานเหมือนเดิม (`lib/formLinks.ts`, cache 60 วินาทีเหมือน `lib/knowledge.ts`)

**ทำไมต้องมีกลไกพิเศษ:** `stripDisallowedLinks` (ข้อ 4 ด้านบน) ปกติจะลบลิงก์เต็มทุกอันออกจากคำตอบเพราะ allowlist ว่างเปล่า — `getFormLinksData()` จึงดึง hostname ของลิงก์ `FormLink` ที่ตั้งไว้มาส่งเป็น `extraAllowedHosts` เฉพาะคำขอนั้นๆ ให้ `stripDisallowedLinks` ปล่อยผ่าน เป็นข้อยกเว้นแคบๆ เฉพาะโฮสต์ที่เจ้าหน้าที่กรอกเองเท่านั้น ไม่ได้แก้ allowlist หลักที่ยังว่างอยู่เหมือนเดิม

**กันโดเมนที่มีปัญหากลับมา (กลไกพร้อมใช้ ปัจจุบันว่างเปล่า):** ตอนบันทึก/แก้ไข `FormLink` (`lib/formLinkValidation.ts`) มีรายชื่อโดเมนต้องห้าม `BLOCKED_FORM_LINK_HOSTS` ที่ระบบจะปฏิเสธ URL เสมอถ้าตรง — เดิมมี `nktscoop.com`/`www.nktscoop.com` อยู่ในนี้ (ตั้งแต่เหตุการณ์ cloaking) แต่เจ้าหน้าที่ยืนยันแล้วว่าเว็บแก้ปัญหานั้นแล้ว จึงปลดออก (ปัจจุบันเซ็ตนี้ว่างเปล่า เหมือน `ALLOWED_LINK_HOSTS` ใน `lib/links.ts`) ถ้าเกิดปัญหาโดเมนไหนในอนาคตอีก เพิ่มกลับเข้าไปในเซ็ตนี้ได้ทันทีโดยไม่ต้องปรับโครงสร้างโค้ด

**นำเข้าลิงก์แบบฟอร์มเป็นชุด:** `npx tsx scripts/import-form-links.ts <path-to-xlsx>` อ่านชีต "แบบฟอร์มสหกรณ์" (คอลัมน์ ลำดับ/หมวดหมู่/ชื่อแบบฟอร์ม/ลิงก์ดาวน์โหลด) แล้ว upsert เข้า `FormLink` โดยใช้เลขลำดับเป็น key (เช่น `form_001`) กันชนกับชื่อแบบฟอร์มภาษาไทยที่ทำ slug ไม่ตรงบ้าง — คำนวณ "ซ้ำ" จากคู่ (หมวดหมู่, ชื่อแบบฟอร์ม) ไม่ใช่ชื่ออย่างเดียว เพราะบางชื่อ (เช่น "หนังสือแจ้งขอบัตรสมาชิก") ตั้งใจให้ซ้ำกันได้ข้ามหมวดหมู่จริง (คนละฟอร์ม คนละลิงก์ สำหรับกองทุน สสอค./สส.ชสอ. ที่ต่างกัน) — กรณีนี้ label จะขึ้นต้นด้วยหมวดหมู่ให้แยกออกจากกันอัตโนมัติ ส่วนกรณีซ้ำจริง (หมวดหมู่+ชื่อเดียวกันเป๊ะ) จะเก็บเฉพาะแถวหลังสุดในไฟล์ไว้ (ถือว่าแถวหลังทับแถวก่อน) แล้ว log แจ้งว่าข้ามแถวไหนไปให้ตรวจสอบได้

### 💰 การแจ้งเตือนธุรกรรม (Transaction Forwarding)
ทุกครั้งที่บันทึกธุรกรรมสำเร็จ (`finalizeTransaction`) ระบบจะแจ้งเจ้าหน้าที่แผนกที่รับผิดชอบพร้อมสลิปแนบ (best-effort — ไม่บล็อกการบันทึกธุรกรรมแม้ส่งไม่สำเร็จ) โดยจับคู่หมวดหมู่ธุรกรรม ↔ แผนกไว้ที่ `lib/categoryDepartments.ts`:

| หมวดหมู่ | แผนก |
| --- | --- |
| ฝากเงิน | เงินฝาก |
| ซื้อหุ้น, ชำระหนี้ | สารสนเทศ |
| ชำระเก็บไม่ได้รายเดือน | สินเชื่อ (ใช้ per-member routing เดียวกับคำขอสินเชื่อ) |
| ชำระประกัน, สสอค, สสชสอ, สสสก, สสสท | สวัสดิการ |
| ชำระฌาปนกิจ, สสค | ฌาปนกิจ |

ผลการส่ง (`forwardedTo`/`forwardStatus`) บันทึกไว้ที่แถว `Expense` เอง ไม่มีตาราง log แยก

### 💻 แดชบอร์ดเจ้าหน้าที่ (Dashboard)
เข้าถึงผ่านหน้าแรก (`/`) ป้องกันด้วย **Basic Auth** (`middleware.ts`) แบ่งเป็นแถบ (`components/Tabs.tsx`) เพื่อไม่ให้ต้องเลื่อนหน้ายาว — แต่ละแถบโหลดข้อมูลเฉพาะตอนเปิดดูครั้งแรก:
* **ธุรกรรม:** ยอดรวมประจำเดือน กราฟแยกหมวดหมู่ ตัวกรอง/คิวตรวจสอบ (`memberVerified = false` เพื่อผูก LINE ID เข้ากับทะเบียนสมาชิก) รายการธุรกรรม ส่งออก CSV (BOM Excel) และฟอร์มบันทึกโดยเจ้าหน้าที่ — ตัวกรองวันที่ของ**รายการ**เริ่มต้นที่ "วันนี้" เสมอตอนเปิดหน้า (มีปุ่ม preset "วันนี้" เพิ่มด้วย) แต่การ์ดสรุป ("ยอดรวมทั้งหมด"/"เดือนนี้") และกราฟทั้งสองจงใจ**ไม่ผูก**กับตัวกรองวันที่ (ยังกรองตามหมวดหมู่/สถานะยืนยันตัวตนได้ปกติ) เพื่อให้ยังเห็นภาพรวมจริงเสมอ ไม่เข้าใจผิดว่าไม่มีข้อมูล (`buildParams`'s `includeDate` option ใน `components/Dashboard.tsx`)
* **คำขอบริการ:** ทะเบียนคำขอส่งต่อเอกสารประกอบ พร้อมรูปถ่ายและเบอร์ติดต่อ พร้อมปุ่ม "เพิ่มเข้าทะเบียน" สำหรับสมาชิกที่ยังไม่ยืนยันตัวตน
* **ผู้รับผิดชอบ:** จัดการรหัสผู้รับผิดชอบฝ่ายสินเชื่อ ↔ LINE UserId (แทนการแก้ผ่านไฟล์ Excel) และเจ้าหน้าที่ผู้รับคำขอของแต่ละแผนกอื่น ได้เองจากหน้านี้
* **ฐานความรู้:** แก้ไขค่าบริการ/ดอกเบี้ย/สวัสดิการในตาราง `KnowledgeEntry` ได้โดยตรง (Cache 60 วินาที) พร้อมส่วน "ลิงก์แบบฟอร์ม" ด้านล่างสำหรับจัดการลิงก์แบบฟอร์มแยกตามประเภท (ดูหัวข้อ "ลิงก์แบบฟอร์ม" ด้านบน)
* **สมาชิก LINE:** ค้นหา/แบ่งหน้ารายชื่อสมาชิกที่เคยทักบอท พร้อมสวิตช์ "บอทตอบอัตโนมัติ" ต่อคน (`LineUser.botPaused`) — ปิดได้เฉพาะรายบุคคลเวลาเจ้าหน้าที่กำลังคุยกับสมาชิกคนนั้นเองใน chat.line.biz โดยไม่กระทบสมาชิกคนอื่น (คนละสวิตช์กับ `messaging_enabled` ในแท็บ "ตั้งค่าระบบ" ที่ปิดทั้งระบบพร้อมกัน — เช็คใน webhook ก่อนแม้แต่ maintenance mode และไม่ตอบข้อความใดๆ เลยแม้แต่ข้อความขอโทษ เพราะเจ้าหน้าที่กำลังตอบเองอยู่แล้ว) ลบรายชื่อรายบุคคลได้ (ปุ่ม "ลบ" มี confirm dialog) — `LineUser` ไม่มี foreign key ผูกกับตารางอื่นเลย (`Expense`/`PendingTransaction`/`PendingServiceRequest`/`PendingMemberLookup` เก็บ `lineUserId` เป็น string เฉยๆ) ลบแล้วกระทบแค่ชื่อเล่น/สถานะ pause ของคนนั้น ประวัติธุรกรรม/คำขอบริการเดิมไม่หายไปไหน และถ้าคนนั้นทักบอทเข้ามาใหม่จะถูกสร้างแถวใหม่ให้อัตโนมัติเหมือนสมาชิกใหม่ (มีประโยชน์ตอนย้ายไปผูกกับ LINE OA ช่องใหม่ — เอาแถวเก่าที่มี LINE user ID ของ OA เดิมทิ้งไปได้) พร้อมเครื่องมือ "ล้างข้อมูลทดสอบ" ลบข้อมูลทุกตารางของเลขสมาชิกทดสอบ (เช่น TEST9999) ในคลิกเดียว แสดงจำนวนแถวให้ตรวจสอบก่อนยืนยันลบ
* **ตั้งค่าระบบ:** สวิตช์เปิด/ปิดฟังก์ชันของบอทได้เอง (`FeatureFlag`, `lib/featureFlags.ts`) ไม่ต้อง deploy ใหม่ มีผลภายใน ~15 วินาที (cache TTL) — แบ่งเป็น "ฟังก์ชันหลัก" 4 ตัว (`messaging_enabled` ปิด = บอทเงียบทั้งหมดทุกคน ไม่ตอบอะไรเลยแม้แต่ข้อความขอโทษ เพราะถือว่าเจ้าหน้าที่จะตอบเองผ่าน chat.line.biz แทน — เช็คที่จุดแรกสุดของ webhook ก่อนเรียก Claude เลย, `transactions_enabled`, `service_requests_enabled`, `member_lookup_enabled` — เช็คในตัว handler ของแต่ละ tool ก่อนเขียน pending state ใดๆ) และ "การแจ้งเตือนรายแผนก" 9 ตัว (`dept_notify_<แผนก>`) ที่ปิดเฉพาะการ push แจ้งเตือนของแผนกนั้น โดยธุรกรรม/คำขอยังถูกบันทึกตามปกติ (สถานะ `muted` ใน `ServiceRequestLog`/`Expense.forwardStatus`) ค่าเริ่มต้นเปิดทุกสวิตช์ ปิดไว้เท่ากับ opt-in ไม่มีอะไรถูกปิดแบบไม่ตั้งใจ

## ⚙️ การตั้งค่าสภาพแวดล้อม (Environment Variables)
คัดลอก `.env.example` ไปเป็น `.env` และตั้งค่าตัวแปรหลัก:
* `DATABASE_URL`: Connection string ของ PostgreSQL
* `LINE_CHANNEL_SECRET` & `LINE_CHANNEL_ACCESS_TOKEN`: คีย์ของ LINE Messaging API
* `ANTHROPIC_API_KEY`: API Key ของ Claude (Anthropic)
* `BLOB_READ_WRITE_TOKEN`: (Optional) token ของ Vercel Blob Store สำหรับสำรองรูปสลิป/เอกสาร — สร้างแบบ **Private** (Vercel ไม่มี Public store ให้เลือกแล้ว) เก็บ/อ่านรูปผ่าน `/api/blob/[...path]` (proxy ในโค้ด ยกเว้นจาก Basic Auth เพราะ LINE ต้องดึงรูปได้โดยไม่มี credential) — ถ้าไม่ตั้งค่า ระบบจะยังทำงานได้ปกติ แค่ไม่มีรูปแนบไปกับข้อความที่ส่งต่อให้เจ้าหน้าที่
* `LINE_FORWARD_LOAN_ID` & `LINE_FORWARD_GENERAL_ID`: LINE ID เจ้าหน้าที่สำหรับส่งต่อคำขอ (ตั้ง `LOG_EVENT_SOURCES=1` ชั่วคราวเพื่อหา ID ใน Log ได้)

## 🛠️ คำสั่งการใช้งาน (Commands)

```bash
# ติดตั้ง Library
npm install

# การจัดการฐานข้อมูล (Prisma)
npx prisma migrate dev       # ตอนพัฒนาในเครื่อง
npx prisma migrate deploy    # ตอนขึ้น Production

# นำเข้าข้อมูลอ้างอิงจาก Excel (ไม่บังคับ)
npx tsx scripts/import-org-data.ts <path-to-file.xlsx>              # นำเข้าสมาชิก/หน่วยงาน (รวมรหัสผู้รับผิดชอบจากคอลัมน์ H, เลขบัตรประชาชนจากคอลัมน์ F, เบอร์โทรจากคอลัมน์ G)
npx tsx scripts/import-responsible-contacts.ts <path-to-file.xlsx>  # นำเข้ารหัส -> LINE UserId ผู้รับผิดชอบ (วิธีจับคู่หลัก)
npx tsx scripts/import-loan-contacts.ts <path-to-file.xlsx>         # นำเข้าผู้รับผิดชอบตามชื่อหน่วยงาน (fallback สำรอง)
npx tsx scripts/import-national-id-phone.ts <path-to-file.xlsx>     # เติมเลขบัตรประชาชน/เบอร์โทรให้สมาชิกที่มีอยู่แล้วเท่านั้น (คอลัมน์ F/G) — ใช้เมื่อไฟล์หลักยังไม่มี 2 คอลัมน์นี้ตอน import-org-data.ts ครั้งแรก ไม่แตะ field อื่นเลย
npx tsx scripts/inspect-responsible-codes.ts <path-to-file.xlsx>    # ตรวจโครงสร้างไฟล์ก่อน import จริง (read-only)
npx tsx scripts/import-form-links.ts <path-to-file.xlsx>            # นำเข้าลิงก์แบบฟอร์มเป็นชุด (คอลัมน์ ลำดับ/หมวดหมู่/ชื่อแบบฟอร์ม/ลิงก์ดาวน์โหลด) — key อิงเลขลำดับ ไม่ใช่ชื่อแบบฟอร์ม

# รันระบบและตรวจสอบ
npm run dev                  # รัน Local server (ตั้ง Webhook ไปที่ /api/line/webhook)
npx tsc --noEmit             # ตรวจสอบ TypeScript
npm test                     # รัน Unit Tests (Vitest)
npm run build                # บิลด์ระบบสำหรับ Deploy
